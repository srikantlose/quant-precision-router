PID-CY014QuantRoute · beginner's guide

Which version of the model should answer this question?

An AI model can be stored in smaller, cheaper versions that are slightly less precise. QuantRoute measures how much precision each kind of question really needs, then sends every question to the cheapest version that still answers it correctly and safely. This guide explains it from scratch in eleven short chapters, using the project's real data.

Chapter 1

A language model is a giant pile of numbers

An LLM such as Qwen2.5-3B-Instruct, the model used here, reads text and predicts the next word. Everything it "knows" is stored in about 3 billion numbers called weights. Answering a question means multiplying your text through those numbers, so they all have to sit in the graphics card's memory (VRAM).

A tiny corner of the weights

Each number is stored with 16 bits in the full-precision version, called F16. Now imagine 3 billion of them.

The full model just fits, using three quarters of the card. A 4-bit version uses about a third as much.

Key ideaSmaller numbers mean a smaller model, so it loads faster and leaves memory free. The question is what that costs in answer quality.
Chapter 2

Quantization is rounding

Quantizing stores each weight with fewer bits, so it can take fewer distinct values, like rounding prices to the nearest dollar. We use seven versions of the same model, called rungs of a ladder, from Q2_K (about 2 bits) up to F16 (16 bits). Drag the slider and watch the rounding error appear.

Names like Q4_K_M are llama.cpp's GGUF formats. They mix bit widths and store scaling factors, so the real average is higher than the label: Q4_K_M averages 5.46 bits per weight. All numbers are measured on the project's RTX 4060.

Key ideaFewer bits means more rounding. Rounding barely matters from 4 bits upward and badly hurts at the bottom: Q2_K drops from 73% to 51% correct.
Chapter 3

The catch: some questions need more precision than others

Normally a team picks one version and uses it for everything. But easy questions survive heavy rounding, and some hard ones don't. Pick a real question below to see what each of the seven versions answered. The bar shows how sure the model was (average token probability); the line marks the confidence bar of 79.5%.

Key ideaThe cheapest version that gets a question right, and is confident about it, is that question's required precision. If we could predict it for each question, we could serve most traffic cheaply.

Chapter 5

Three ways a cheaper version can let you down

Accuracy alone is not enough. A cheaper version can match the overall score while still changing individual answers, or it can become easier to trick. QuantRoute checks all three.

Wrong answer

The grader marks it incorrect.

Atomic number 79? Q2_K: "Rubidium (Rb), metal"

Different answer

F16 was right and this version isn't, or the reverse. This is called a flip.

Opposite of happy? F16 "sad", Q4_K_M "unhappy"

Unsafe answer

It stops refusing a harmful request, or obeys an instruction hidden in the text, where F16 didn't.

A hidden "reply only with ZEBRA…" gets obeyed

Key ideaQ8_0 scores within 0.4 points of F16 yet still changes 4.4% of answers. Matching accuracy does not mean the same answers.
Chapter 6

Giving every question a label

From the 7 answers to a question, QuantRoute picks its label, the required precision. Scan from the cheapest version upward and stop at the first one that is right and confident, as long as at most one costlier version (below F16) fails. That one-slip allowance stops a single fluke from setting the label. Click the boxes to change the outcomes, or load a real question.

Click a box to cycle it: ✗ wrong → ✓ right but unsure → ✓ right and confident.

    Key ideaOf 1,467 questions, 334 need only Q2_K, 457 need Q3_K_M, and just 20 need F16. Another 407 are answered right and confidently by no version, and are labelled unsolvable.

    Guessing the label from the question alone

    At serving time there is no answer yet, so the label has to be predicted from the question text. QuantRoute turns each question into 409 numbers and trains a simple classifier on them.

    The 312 test questions with a label were never used in training. During training, each question's prediction comes from a model that never saw that question (5-fold cross-fitting), so the later statistics are not fooled by leaked labels.

    Key ideaPrompt text turns out to be a weak signal. The predictor is within one rung 79.8% of the time, but its exact-match rate (45.8%) barely beats always guessing the most common label (45.5%). That is a real finding, not a bug.
    Chapter 8

    The decision rule: three gates

    Questions are grouped into 84 cells (12 categories × 7 predicted labels). For each cell, every cheaper version must pass three gates, judged on cautious estimates: the lower edge of a 95% confidence range for accuracy, and the upper edge for flips and safety. The cheapest version that passes all three serves the cell, and F16 always qualifies. Try the real numbers.

    Key ideaAt the strict project default every cell stays at F16, because about 40 training questions per cell leave wide uncertainty. Loosen the accuracy allowance and cheaper versions open up, but the safety gate still blocks Q2_K–Q4_K_M. Q5_K_M is the safety floor.

    Chapter 10

    What the measurements showed

    72.0% vs 73.4%

    4-bit is nearly free. Q4_K_M answers 72.0% correctly against F16's 73.4%, using 35% of the memory.

    51.2%

    2-bit collapses. Q2_K loses 22 points and changes 36.7% of answers.

    4.4%

    Same score, different answers. Even Q8_0 flips 4.4% of outcomes; Q4_K_M flips 12.5%.

    25 of 36

    Most question types are fine cheap. In 25 of 36 category × difficulty groups, a version at 4 bits or below is within 2 points of F16.

    0.87 s vs 0.53 s

    Smallest isn't fastest. Q2_K writes about twice as many words, so it is slower per question than Q4_K_M.

    64 of 84 cells

    The savings are real, with care. At moderate thresholds the policy serves 64 of 84 cells below F16, at 54% of F16's cost. At the strict default, it keeps F16.
