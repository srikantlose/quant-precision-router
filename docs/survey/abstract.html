QuantRoute: Serving Each LLM Prompt at the Cheapest Quantization Level That Stays Accurate and Safe

ABSTRACT

Running a large language model on a single consumer GPU forces a choice of quantization level — how many bits each weight keeps — and that choice is usually made once, by convention, for all traffic. Yet the literature shows that quantization damage is strongly task-dependent and that matching accuracy can hide large numbers of changed answers. This project asks whether the right precision depends on the prompt, and builds a system that chooses it. Qwen2.5-3B-Instruct is served at seven GGUF quantization levels (Q2_K to F16) through llama.cpp on an 8 GB RTX 4060 and evaluated on 1,467 graded tasks spanning 12 categories and three difficulty tiers, plus a 600-prompt safety slice built from XSTest and planted prompt injections — 14,469 graded runs in total, with every model file pinned by its SHA-256 hash and model-written code graded inside a locked-down Docker sandbox. For each run the system records accuracy, answer flips and KL-divergence against F16, safety behaviour, and measured cost (VRAM, latency and load time). Each task is labelled with its required precision — the cheapest level that solves it confidently — and a cross-fitted predictor estimates that label from the prompt alone. A selection policy, fitted with task-clustered statistical models, then serves the cheapest level whose accuracy, answer-stability and safety bounds all pass. Q4_K_M comes within 1.4 points of F16’s accuracy at 35% of F16’s memory, while Q2_K collapses to 51%; even Q8_0 changes 4.4% of answers; and in 25 of 36 category–difficulty cells a level of 4 bits or less comes within 2 points of F16. At moderate thresholds the policy serves 64 of 84 cells below F16 at 54% of the cost, while prompt text proves only a weak predictor of required precision (79.8% within one level). The work is delivered with an interactive results dashboard and study guide, with a hardened routing API and adversarial evaluation of the router as the next stage.
